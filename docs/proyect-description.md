# **Descripción / Contexto**

## Visión general

Una empresa brinda servicios técnicos y de mantenimiento a clientes que cuentan con diferentes sedes, instalaciones y equipos que requieren atención periódica, reparaciones o intervenciones específicas.
La operación involucra diferentes etapas y personas: el área administrativa recibe una solicitud o identifica una necesidad de mantenimiento, se genera una Orden de Trabajo (OT), se determina el tipo de servicio requerido y se asigna un técnico disponible para realizar la intervención en la ubicación correspondiente.
Los técnicos trabajan fuera de la oficina y necesitan acceder desde el campo a la información necesaria para ejecutar correctamente cada trabajo y registrar lo realizado.

### Información asociada al proceso

Durante este proceso se generan y utilizan diferentes tipos de información:

* Clientes.
* Sedes e instalaciones.
* Equipos.
* Órdenes de Trabajo.
* Tipos de servicio.
* Técnicos.
* Disponibilidad y asignaciones.
* Agenda de trabajo.
* Estados de las intervenciones.
* Checklists.
* Fotos y evidencia.
* Notas técnicas.
* Firma o conformidad del cliente.
* Historial de mantenimiento.
* Mantenimientos preventivos.
* Recurrencias.

Actualmente, gran parte de esta información puede administrarse mediante planillas, mensajes, llamadas, sistemas administrativos y registros realizados por los propios técnicos, lo que dificulta mantener una visión centralizada de las tareas pendientes, las intervenciones en curso y el historial de cada equipo.
El problema no está únicamente en coordinar técnicos, sino en conectar la planificación del trabajo con lo que realmente ocurre en campo y mantener evidencia de cada intervención.

### Pregunta clave para la operación

Ante una consulta, reclamo o necesidad de mantenimiento, la empresa necesita poder responder rápidamente:

**¿Qué cliente solicitó el servicio, dónde está el equipo, qué trabajo debía realizarse, qué técnico fue asignado, qué se hizo, cuándo se realizó, qué evidencia existe y cuál es el estado actual del equipo?**

FieldFlow busca resolver esta problemática mediante un sistema centralizado de gestión, planificación, ejecución y trazabilidad de servicios técnicos en campo.

# **Problema / Dolor del negocio**

La gestión de técnicos y mantenimientos mediante diferentes herramientas y canales genera una serie de problemas operativos.

## 1. Falta de trazabilidad

La información de una intervención puede encontrarse distribuida entre la administración, el técnico y diferentes registros.
Esto dificulta reconstruir el historial completo de un servicio desde su solicitud hasta su finalización.

## 2. Información dispersa

Los datos del cliente, ubicación, equipo, orden de trabajo, instrucciones, fotografías y resultado de la intervención pueden encontrarse en diferentes lugares.
Esto dificulta que el técnico tenga toda la información necesaria al momento de realizar el trabajo.

## 3. Dificultad para planificar técnicos

La asignación de trabajos requiere considerar:

* Disponibilidad del técnico.
* Tipo de servicio.
* Ubicación.
* Agenda.
* Prioridad.
* Duración estimada.

Cuando esta planificación se realiza manualmente, puede generar asignaciones poco eficientes, demoras y dificultades para reorganizar la agenda ante cambios o imprevistos.

## 4. Dificultad para realizar seguimiento

La empresa necesita conocer en todo momento qué está ocurriendo con las órdenes de trabajo.
Por ejemplo:

* Pendiente.
* Asignada.
* En camino.
* En ejecución.
* Pendiente de conformidad.
* Finalizada.
* Reprogramada.

Sin un estado centralizado, resulta difícil conocer la situación real de las operaciones en campo.

## 5. Falta de evidencia del trabajo realizado

Una intervención técnica necesita quedar respaldada por evidencia que permita demostrar qué trabajo se realizó.
Esta evidencia puede incluir:

* Fotografías.
* Notas.
* Checklists.
* Mediciones.
* Observaciones.
* Firma o conformidad del cliente.

Cuando estos registros se realizan fuera de un sistema centralizado, pueden perderse o quedar asociados de manera incorrecta a la intervención.

## 6. Dificultad para consultar el historial de los equipos

Un equipo puede recibir múltiples intervenciones a lo largo del tiempo.
Si cada mantenimiento se registra de manera independiente, resulta difícil conocer:

* Qué fallas tuvo.
* Qué reparaciones recibió.
* Qué componentes fueron intervenidos.
* Cuándo fue su último mantenimiento.
* Qué tareas se realizaron anteriormente.

Esto dificulta detectar problemas recurrentes y planificar futuras intervenciones.

## 7. Dificultad para gestionar mantenimiento preventivo

Los mantenimientos preventivos requieren programar intervenciones antes de que ocurra una falla.
Sin un sistema que gestione recurrencias y fechas previstas, existe el riesgo de:

* Olvidar mantenimientos.
* Realizarlos fuera de fecha.
* Generar interrupciones innecesarias.
* Perder continuidad sobre el mantenimiento de los equipos.

# **Oportunidad**

La oportunidad consiste en transformar la operación actual en un flujo digital centralizado y trazable, donde cada servicio pueda ser planificado, asignado, ejecutado y documentado desde una única plataforma.

El sistema debería permitir pasar de:

**Cliente → Sede → Equipo → Orden de Trabajo → Asignación → Agenda → Intervención → Evidencia → Conformidad → Historial**

manteniendo la información asociada durante todo el ciclo.

El objetivo no es simplemente reemplazar las planillas utilizadas por los técnicos.
El objetivo es construir una fuente única de información para las operaciones en campo, donde administración pueda planificar y realizar seguimiento, mientras que los técnicos puedan consultar la información necesaria, registrar el trabajo ejecutado y generar evidencia directamente desde el lugar de la intervención.

---

# **CRITERIO DE ÉXITO DEL PROYECTO**

El proyecto será exitoso si un usuario puede tomar una Orden de Trabajo y, sin necesidad de buscar información en diferentes sistemas, planillas o canales de comunicación, conocer el cliente, la ubicación y el equipo involucrado, consultar el técnico asignado y el estado del servicio, y acceder al registro completo de la intervención, incluyendo checklist, fotografías, notas, conformidad e historial de mantenimiento.
